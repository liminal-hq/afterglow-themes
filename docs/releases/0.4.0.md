**Afterglow 0.4.0** brings the Afterglow look to the ReactOS desktop, with a visual style, eight colour schemes, pointers, wallpapers, logon, boot and Start art and a 73-icon set, and adds themes for Forgejo.

## What is new

### ReactOS desktop and wallpapers

- **Visual style.** `afterglow.msstyles` is a visual style for ReactOS 0.4.16: dusk captions, a near-black taskbar with a gold Start button, rose and gold accents and classic cream client areas. It is drawn from source by a generator under `desktop/` and the build is reproducible, so `SHA256SUMS` records the exact bytes. The default build uses classic Windows scroll bars; the zip also carries a second build with the Afterglow scroll bars (`style-scrollbars/`), and you use one or the other.
- **Eight colour schemes.** Dusk (the default), Ember, Aurora and Graphite, each in a dark and a light version, as `.reg` files with `apply-scheme.cmd`. Title text keeps 4.5:1 contrast on every caption in every scheme, and the generator refuses to build otherwise.
- **Pointers.** Fourteen `.cur` pointers and two animated `.ani` pointers in one set that works on every scheme, with `afterglow-pointers.reg` to list them as a scheme in Control Panel, Mouse. ReactOS 0.4.16 ignores pointer schemes, so `patch-user32.py` patches your own copy of the 0.4.16 i386 `user32.dll` to make them the system pointers. The tool refuses any other build and never writes over its input, and no patched binary is shipped.
- **SVG masters.** Vector masters of all 14 pointers (with the hot spot recorded in each file) and animated SVGs of the working and busy pointers, as scalable reference art. The `.cur` and `.ani` files are what ships to ReactOS.
- **Wallpapers.** Twenty SVG wallpapers at 3840 × 2160: five palettes (Dusk, Indigo, Ember, Aurora and Graphite), each in dark (a low sun setting over layered horizons) and light (full day), with stepped or smooth bands. The centre is kept calm so icon labels stay readable, and the front horizon sits behind the taskbar. They work on any desktop, not only ReactOS.
- **Logon banner.** The Afterglow logon banner and the bar under it, drawn as vector masters (`banner-a.svg` and `bar.svg`, with `banner-b.svg` kept as a fallback) and rendered by script to the 413 × 72 and 413 × 5 24-bit BMPs the ReactOS logon boxes use, with their hashes recorded. The banner text reads "for ReactOS · unofficial remaster". The images are patched into the logon by the remaster build, not by this repository, and the zip carries no patched `msgina.dll`.
- **Boot logo.** The logo on the ReactOS kernel boot screen, drawn as a vector master and rendered to the exact 414 × 366 16-colour bitmap the kernel resource needs, uncompressed and as RLE4 (11,288 bytes, which fits the 16,504-byte slot). The 16 colours are the palette of the whole boot screen, because the kernel loads that one palette for everything, so `palette.json` records each entry with its role and the progress bar's box stays empty. The palette is stored at 8 bits a channel and the display keeps the top six, so the renderer snaps to the six-bit values. The zip carries no patched kernel.
- **Start orb and menu banner.** The Afterglow dusk badge (a navy disc with a gold sun half set on its horizon) and a dusk banner with the Afterglow name, drawn as vector masters (`orb.svg` and `banner.svg`) and rendered to the resource-ready DIBs for explorer.exe: the 25 × 20 32-bit orb with straight alpha, which keeps a transparent margin inside the 20 × 20 square explorer shows, and the 21 × 233 24-bit banner that starts in the menu's navy. The zip carries no patched `explorer.exe`.
- **Icon set.** Seventy-three icons (shell objects, Control Panel applets, drives, file types, dialogs, the Explorer toolbar, the tray and the Start menu) drawn as vector masters in the language of the Afterglow folder and rendered to 74 `.ico` files with 16, 32 and 48 px frames, with the G-M1 folder family. `arrow.ico` is the original A1 shortcut arrow, a paper coin with a dusk-navy arrow, and replaces shell32 group 30. `map.json` maps each icon to the ReactOS icon it replaces, with the shell32 group ids that were verified; the 19 icons with no ReactOS counterpart named yet (the toolbar glyphs and the tray icons among them) are marked unmapped. Seventeen icons carry a hand-drawn 16 px frame.
- **Release bundles.** `afterglow-wallpapers-v0.4.0.zip` and `afterglow-reactos-desktop-v0.4.0.zip` join the release and `SHA256SUMS`. The links in the docs inside the ReactOS zip are rewritten to its layout and checked, so every one resolves.
- **CI check.** A `Desktop style` job rebuilds both styles, the schemes, the pointers, the SVG masters and the logon, boot, Start and icon art on every change and compares them with the recorded hashes.

### Forgejo

- **Four themes.** `afterglow`, `afterglow-dark`, `afterglow-light` and `afterglow-auto`, generated from the shared palette. Each imports Forgejo's own dark or light theme and recolours its grey ramp and primary colour, so Forgejo's syntax colours, diffs and alerts stay as it draws them. `afterglow` is the signature dark theme and never follows the system; `afterglow-auto` follows it.
- **Instance avatar.** An Afterglow picture for the "Signed by" line on commits Forgejo signs itself, and an installer that writes the stylesheet for a given signing email.

### Maintenance

- **Dependabot.** Dependabot no longer opens pull requests, so dependency updates are made by hand.
- **Dependencies.** The development dependencies and the workflow actions are updated.

## Fixes

- **Python bytecode.** The ReactOS style build no longer leaves Python bytecode in the style folder.
- **Forgejo avatar.** A redrawn instance avatar loads straight away instead of waiting on a cached copy.
- **Release docs.** The docs in the ReactOS desktop zip no longer link to files outside the zip.

## Known limits

- **Not tried on real hardware.** The ReactOS desktop has been seen only in a ReactOS 0.4.16 guest in QEMU. Nothing has been run on a physical machine.
- **Pointers are for a demo disk.** The `user32.dll` patch supports one build only (ReactOS 0.4.16 for i386, 1,604,096 bytes) and is meant for your own demo disk. A patched `user32.dll` is ReactOS code and is not distributed here. The system busy pointer does not animate.
- **One pointer set.** A lighter pointer variant for the light schemes is not built.
- **Not all of the style is checked.** The default classic scroll bars were seen in Notepad in the guest; the Afterglow scroll bar build was not looked at again, and the wallpapers have not been set as the background on a real ReactOS, Windows, GNOME or KDE desktop. White icon labels on the light wallpapers rely on their drop shadow.
- **New art not seen in a booted shell.** This repository's CI never boots ReactOS, so none of the logon, boot, Start or icon art has been seen in a booted ReactOS shell by it. A preview VM applied the kernel boot logo, the Start orb and the menu banner only, with an earlier generator; the icon `.ico` files and the logon banner have not been applied to a booted ReactOS yet. The patching happens in the reactos-liminal build and is guarded by the hashes of the ReactOS files.
- **Icons.** Only 17 icons have a hand-drawn 16 px frame; the other 56 have scaled 16 px versions. The 19 unmapped icons have no ReactOS counterpart named yet.
- **Render hashes.** The BMP, DIB and `.ico` hashes depend on the `rsvg-convert` (librsvg and cairo) anti-aliasing and on Pillow.
- **SVG pointers.** The vector masters overlap the shipped raster pointers by about 87%, and the animated SVGs were not played in a browser.
- **Forgejo.** Only `afterglow` and `afterglow-light` were checked by eye, on the sign-in page of a Forgejo 16.0.3 instance. Signed-in pages (repositories, diffs, pull requests), `afterglow-dark`, `afterglow-auto`, the `THEMES` setting end to end and the avatar on a commit page were not checked. Forgejo's syntax colours do not follow Afterglow.
- **Reproducibility.** The pointer hashes depend on Pillow 13.0.0, so a different Pillow can change them.
- **Other targets.** The OpenCode, VS Code, Midnight Commander, Claude Code, TextMate and browser themes are unchanged apart from the version number. The Firefox themes are unsigned.
